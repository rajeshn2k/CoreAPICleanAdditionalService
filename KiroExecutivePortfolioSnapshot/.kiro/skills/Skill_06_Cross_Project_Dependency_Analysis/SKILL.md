# Skill 6 — Cross-Project Dependency Analysis

## Purpose
Find shared dependencies, conflicting milestone dates, competing funding needs, and other documented relationships between projects.

## Procedure
1. Review approved schedules, dependency registers, funding requests, resource plans, and governance records.
2. Capture predecessor/provider, dependent project/activity, required date, owner, status, and source.
3. Check for date conflicts, missing prerequisite decisions, shared resource constraints, competing funding, and downstream effects.
4. Distinguish confirmed dependencies from suspected relationships.
5. Explain impact on a dependent milestone only where evidence supports it.
6. Flag missing owners/dates and conflicts across sources.
7. Do not infer critical-path impact unless schedule logic and required data support that conclusion.

## Required output
Dependency, providing project/team, dependent project/activity, required date/status, owners if evidenced, documented downstream impact, funding/resource conflict if applicable, source/date, classification/confidence, and coordination needed.

## Guardrails
Do not invent dependency links, dates, owners, or impacts. Similar dates alone do not prove a dependency. Do not modify schedules.

## Completion check
Each dependency is traceable and confirmed relationships are distinguished from suspected ones.
